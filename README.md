# Mahmoud Hassan – Digital Marketing Portfolio

## Project Overview

A responsive, single-page portfolio for Mahmoud Hassan, a Cairo-based Digital Marketing Specialist and Social Media Strategist. It presents his services, skills, tools, workflow, and project concepts for businesses in Egypt and the wider Arab market.

This is an illustrative portfolio. Statistics, project case studies, and testimonials are fictional demo content; they are not verified client results or real customer reviews.

## About the Owner

**Mahmoud Hassan – Digital Marketing Specialist | Social Media Strategist**  
Based in Cairo, Egypt.

## Main Features

- Responsive layout for desktop, tablet, and mobile screens.
- Light and dark themes. The selected theme is saved in the browser; first visits follow the system color preference.
- Hero and About sections with a profile photo and downloadable CV.
- Services for social media management, Meta Ads, Google Ads, SEO, content creation, and digital marketing strategy.
- Core marketing skills and tools/platforms.
- A dedicated **How I Work** section: Audience Research, Goal-Oriented Planning, Content Strategy, Campaign Execution, Performance Monitoring, and Continuous Optimization.
- Portfolio cards with detail dialogs. All case studies are fictional demo projects.
- Sample testimonials clearly labeled as demo content.
- Contact form with required-field and email validation and optional Formspree delivery.
- Social profile placeholders are visibly marked and are not clickable. No personal profile URLs are configured.
- Scroll-triggered section reveal animations.

## Technologies Used

These technologies are used by the project and listed in `package.json`:

- **React 18** and **React DOM** for the interface.
- **TypeScript** for typed application code.
- **Vite 6** and `@vitejs/plugin-react` for development and production builds.
- **Tailwind CSS 3** and custom CSS in `src/index.css`; Tailwind dark mode uses the `class` strategy.
- **Lucide React** for icons.
- **PostCSS** and **Autoprefixer** in the CSS build pipeline.
- **DM Sans** and **Manrope** fonts loaded from Google Fonts, with sans-serif fallbacks.

## Installation

1. Download and extract the project ZIP from its repository or project page, or open the existing project checkout.
2. Install Node.js and npm if needed.
3. Open a terminal in the project root, where `package.json` and `package-lock.json` are located.
4. Install the locked dependencies:

```sh
npm ci
```

## Run Locally

Start the Vite development server:

```sh
npm run dev
```

Open the local address printed in the terminal.

## Contact Form Configuration

The form checks its required fields and email address before submission. It sends a JSON `POST` request to Formspree only when an endpoint is configured. A success message is shown only after the service returns a successful response. If no endpoint is set, the form says message delivery is unavailable and directs visitors to the displayed email address; network or service failures show an error message.

To enable Formspree delivery locally:

1. Copy `.env.example` to `.env.local`.
2. Set `VITE_FORMSPREE_ENDPOINT` in `.env.local` to the endpoint for your Formspree form.
3. Restart the development server.

`.env.local` is ignored by Git. Do not commit private configuration values.

## Production Build

Create the optimized production build:

```sh
npm run build
```

This runs `tsc -b` followed by `vite build`. The generated static site is written to `dist/`.

To preview the production build locally, build first and then run:

```sh
npm run preview
```

Open the preview address printed in the terminal.

## Deployment

The Vite build outputs static files and can be deployed to a static hosting provider such as Vercel or Netlify:

1. Push the project to a Git repository you control.
2. Import that repository into your chosen hosting provider.
3. Use `npm ci` as the install command, `npm run build` as the build command, and `dist` as the output/publish directory.
4. To enable form delivery, add `VITE_FORMSPREE_ENDPOINT` in the provider's environment-variable settings.

The provider will build and publish the contents of `dist/`. Keep configuration values out of the repository and README.
